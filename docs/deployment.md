# Deployment Guide

## Overview

Veris is deployed as three separate services:

- React frontend on Vercel
- Node.js and Express backend on Render
- MongoDB Atlas for persistence

This separation keeps the UI, API, and database independent so each layer can be updated without redeploying the others.

---

## Deployment Targets

| Component | Technology | Platform |
|-----------|------------|----------|
| Frontend | React + Vite | Vercel |
| Backend | Node.js + Express | Render |
| Database | MongoDB | MongoDB Atlas |

### Production URLs

- Frontend: https://veris-ruby.vercel.app
- Backend API: https://veris-g3jt.onrender.com/api

### Local Development URLs

- Frontend: http://localhost:5173
- Backend API: http://localhost:5000/api

---

## Backend Environment Variables

| Variable | Description |
|----------|-------------|
| PORT | Server port used by Express. |
| MONGO_URI | MongoDB Atlas connection string. |
| JWT_SECRET | Secret used to sign and verify JWT tokens. |
| WHOIS_API_KEY | API key for WHOIS lookup services. |

Example:

```env
PORT=5000
MONGO_URI=your_mongodb_connection_string
JWT_SECRET=your_secret_key
WHOIS_API_KEY=your_api_key
```

## Build And Release Flow

1. Code is pushed to GitHub.
2. Vercel builds the frontend from the `frontend/` project.
3. Render builds the backend from the `backend/` project.
4. Render starts the Express server and connects it to MongoDB Atlas.
5. The frontend calls the deployed backend using REST APIs.
6. Users access the app through the deployed frontend.

```text
Developer
    │
    ▼
GitHub Repository
    │
    ├──────────────► Vercel (Frontend)
    │
    └──────────────► Render (Backend)
                                             │
                                             ▼
                                MongoDB Atlas
```

---

## Deployment Notes

- The backend must allow the deployed frontend origin through its CORS settings.
- The MongoDB connection string should come from environment settings, not source control.
- Authentication tokens are generated by the backend and consumed by the frontend after login or registration.
- The validation workflow depends on outbound network access for WHOIS, SSL, and website checks.

---

## Operational Considerations

- Keep Render and MongoDB Atlas credentials out of the repository.
- Rebuild the frontend after UI changes and the backend after API or scoring changes.
- Use the cached validation flow for normal scans and force refresh only when a fresh result is required.
- Monitor validation failures separately from authentication errors because they usually have different causes.
